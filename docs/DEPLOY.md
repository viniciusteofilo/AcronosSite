# Deploying ACRONOS (Cloudflare Workers + Neon + R2)

| Piece | What it does | Plan |
| --- | --- | --- |
| Cloudflare Workers | Runs the site (Next.js built with OpenNext) close to visitors | **Workers Paid, US$5/month** — needs ACRONOS authorization (see below) |
| Cloudflare R2 | Product and campaign photos; page cache | Free tier (10 GB) |
| Cloudflare Hyperdrive | Fast, pooled connection from the Worker to the database | Included |
| Neon | PostgreSQL database with point-in-time history | Free tier to start (0.5 GB) |
| GitHub Actions | Tests on every change; deploys when you press "Run" | Free |

**Why the paid Workers plan:**
- The site's Worker is about 4 MiB compressed, and the free plan accepts 3 MiB.
- Each sign-in hashes the password on purpose, which uses more than the free plan's 10 ms of CPU per request.

## One-time setup (ACRONOS)

1. **Cloudflare.**
   - Create an account at dash.cloudflare.com.
   - Subscribe to *Workers Paid* (after approving the cost).
   - Copy the **Account ID** (right column of the Workers page).
2. **Cloudflare API token.**
   - Go to My Profile → API Tokens → Create Token → *Custom token*.
   - Give it these account permissions:
     - Workers Scripts: Edit
     - Workers R2 Storage: Edit
     - Hyperdrive: Edit
     - Account Settings: Read
3. **Neon.**
   - Create an account at neon.tech.
   - Create a project in region **AWS US East** with **PostgreSQL 16**.
   - Copy the **direct** connection string (not the "pooled" one). It ends with `?sslmode=require`.
4. **GitHub.**
   - Open the repository → Settings → Secrets and variables → Actions.
   - Create the environment `production` and add these secrets:
     - `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`
     - `NEON_DATABASE_URL`
     - `BETTER_AUTH_SECRET`: 48+ random characters, generated by a password manager. **Never change it**: it encrypts the two-factor keys.
     - `CRON_SECRET`: 32+ random characters.
     - Later, when the accounts exist: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID`.

## First deploy (on the free *.workers.dev address, no DNS change)

1. Merge pull requests #1 → #8 into `main`, in order.
2. Go to Actions → **Deploy** → Run workflow. Use the site URL `https://acronos-site.<your-subdomain>.workers.dev` (Cloudflare shows the subdomain on the Workers page). The workflow then:
   1. Backs up the database. The first run has nothing to back up.
   2. Applies the migrations.
   3. Creates the R2 buckets and Hyperdrive if needed.
   4. Builds the site.
   5. Uploads the secrets.
   6. Deploys.
   7. Checks that the home and shop pages answer.
3. Create your account on the live site (Sign in → Create account).
4. Actions → **First super admin** → Run workflow with your e-mail. It runs only once and refuses if a super admin already exists.
5. Sign in, turn on two-factor at `/account/security`, then open `/admin`.

## Domain (needs ACRONOS authorization before any DNS change)

1. Cloudflare → Add a domain → `acronos.com.br` (Free plan). Cloudflare lists the existing DNS records: keep e-mail (MX) records as they are.
2. At Registro.br, replace the nameservers with the two Cloudflare gives you. This is the DNS change. It takes up to a few hours.
3. Workers → acronos-site → Settings → Domains & Routes → add `acronos.com.br` and `www.acronos.com.br`.
4. Run **Deploy** again with `https://acronos.com.br`.
5. Update the Stripe and PayPal webhook addresses to the new domain.

**Moving to a domain without .br later:**
1. Repeat steps 1–4 with the new domain.
2. Redirect the old one to it: Cloudflare → Rules → Redirect Rules (301).

## Operations

- **Cron:** every 10 minutes the Worker frees stock held by abandoned checkouts and removes expired sessions (`/api/cron/maintenance`, protected by `CRON_SECRET`).
- **Logs:** Cloudflare → Workers → acronos-site → Observability.
- **Backups:**
  - Each deploy uploads a database dump as a workflow artifact, kept 30 days.
  - Neon keeps point-in-time history.
  - See `docs/OPERATIONS.md` for the restore drill.
- **Rollback:** Cloudflare → Workers → acronos-site → Deployments → roll back to the previous version. Database migrations only add things, so older code keeps working.

## Local test of the Cloudflare build

```bash
npm run cf:preview   # builds with OpenNext and runs the site in the Workers runtime on :8787
```

`.dev.vars` (git-ignored) holds `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `SITE_URL` and `CRON_SECRET` for the preview. Hyperdrive uses `localConnectionString` from `wrangler.jsonc` (the local development database).
